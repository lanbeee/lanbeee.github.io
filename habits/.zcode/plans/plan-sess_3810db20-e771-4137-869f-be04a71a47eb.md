## Goal
Make an app shortcut open the **installed app itself** on tap when possible, with the store page as the automatic fallback when it isn't installed.

## Why it can't be automatic (the honest constraint)
Apple exposes **no mapping** from an App Store ID to the app's deep link (its `spotify://`-style scheme or universal link), and a web page cannot launch an app by ID. Guessing schemes from app names misfires (wrong/missing schemes). So the direct link must be supplied **once per app** as an optional field — after that, every tap is one-step.

## Changes

### 1. Data model — `js/data-normalize.js` + `js/data-schemas.js`
- `normalizeLinks`: keep an optional `launch` field for `kind:'app'` when it normalizes to a valid safe URL and differs from `value` → stored shape `{kind:'app', value, label?, launch?}`. (Normalization is where links are rebuilt, so save/import/backup round-trips all keep it automatically.)
- New PURE `linkDirectLaunchUrl(link)`: normalized `launch` or `''` (non-app kinds, invalid, or identical to `value` → `''`).
- Update the `links` JSDoc in `js/data-schemas.js` (~line 131).

### 2. Launch flow — `js/shell-ui.js` `openHabitLink` (single funnel for card double-tap + detail header buttons)
- If a direct link is set:
  - **App scheme** (OS handoff): `location.href = scheme`, then a ~1.5s guarded fallback — canceled if the page hides (the app took over); if the page is still visible, open the stored URL (store page) exactly as today. Classic scheme-then-store pattern.
  - **https direct link** (universal link): open it directly — the target page itself handles not-installed.
- No `launch` → today's behavior, byte-for-byte.

### 3. Custom app editor — `index.html`, `css/detail.css`, `js/detail-view-tune.js`
- New optional input `#detail-custom-app-launch` ("opens the app directly — optional", placeholder `app link e.g. spotify://`), as a second row in the editor grid (320px fit preserved and still tested).
- `addCustomDetailApp` includes it when set; `closeDetailAppPicker` resets it.
- Built-in presets stay unchanged — no guessed schemes.

### 4. Row editor (edit an existing app shortcut later)
- App-kind rows gain a third line input (`.link-app-launch`), hidden for non-app kinds exactly like the app-name input today; `currentDetailLinkRows` reads it back; `syncDetailLinkUi` toggles it on kind change.

### 5. Docs — `DOCUMENTATION.md`
- Field list (~line 419) + §9.7 links section: explain the optional direct link, the fallback behavior, and why the store ID alone can't deep-link.

### 6. `sw.js` — bump `CACHE` to `tings-v208`.

### 7. Tests — `tests/links-and-maps-test.js`
- Pure: `launch` kept when valid+distinct, dropped when invalid/equal/non-app; `linkDirectLaunchUrl` routing.
- Fallback behavior with stubbed `window.open`: a `roku://`-style scheme that (in the test browser) never hides the page → the store URL lands in `window.__opened` within ~2.5s; no-`launch` links still open immediately.
- Editor: custom app saved with a direct link; row editor shows/hides the input with kind; persistence via `load()`.
